# ADR 0010: Google MCP Toolbox for Databases Architecture

## Status
Accepted

## Context
OmniMission AI agents require governed, secure access to physical store inventory, aisle coordinates, and dietary substitutions. Giving an AI model direct SQL access or unstructured tool calling poses significant risks:
1. **Unconstrained mutation risk:** Accidental `UPDATE`, `DELETE`, or `DROP` statements generated by hallucinating LLMs.
2. **Schema leakage:** Exposing internal system tables, user credentials, JWT hashes, or raw trace logs to agent reasoning contexts.
3. **Grounding violation:** If the agent fabricates quantities or aisle numbers without verifying with the physical store database, shoppers are misdirected inside physical aisles.
4. **Cloud Portability:** The solution must be local-first in Phase 2 using local PostgreSQL, but seamlessly migrate to Google Cloud (Cloud SQL for PostgreSQL / AlloyDB) in GCP deployment.

## Decision
1. **Adopt Google MCP Toolbox for Databases (`googleapis/mcp-toolbox`):**
   - Use Google's open-source MCP Server for Databases as the standard database tool provider for Agno agents.
   - Declarative `infra/toolbox/tools.yaml` defines read-only parameterized PostgreSQL tools (`kind: postgres-sql`) using `$1, $2` parameter binding to eliminate SQL injection.
   - Pin image `ghcr.io/googleapis/genai-toolbox:latest` as an independent container service in `docker-compose.yml`.

2. **Dedicated Read-Only Postgres Role (`toolbox_ro`):**
   - Enforce database-level least privilege with a dedicated database role `toolbox_ro`.
   - `toolbox_ro` is granted `SELECT` strictly on curated database views (`v_store_inventory`, `v_product_details`, `v_aisle_locations`, `v_store_details`, `v_dietary_substitutes`).
   - Direct access to underlying base tables (`users`, `refresh_tokens`, `mission_traces`) is revoked.

3. **Hexagonal Architecture (`DataToolPort` & `ToolboxGateway`):**
   - `DataToolPort` (`apps/api/src/omnimission/ports/data_tool_port.py`) abstracts inventory search, stock verification, and physical coordinates.
   - `ToolboxGateway` (`apps/api/src/omnimission/adapters/toolbox_gateway.py`) implements `DataToolPort`:
     - Provides native typed query execution with identical parameterized semantics for local unit testing and low-latency internal services.
     - Exposes typed Agno tool functions (`get_agno_tools()`) compatible with Agno's `Agent(tools=...)` and `MCPTools`.

## Consequences
- **Strict Grounding Invariant:** Agents can only read real-time inventory and physical aisle locations through curated, verified views.
- **Defense in Depth:** Even if prompt injection instructs an agent to alter records, the underlying Postgres role (`toolbox_ro`) and parameterized view queries render data mutation impossible.
- **Drop-in GCP Readiness:** In production GCP, the `tools.yaml` source configuration switches from `kind: postgres` to `kind: cloud-sql-postgres` or `kind: alloydb` with zero application code changes.
